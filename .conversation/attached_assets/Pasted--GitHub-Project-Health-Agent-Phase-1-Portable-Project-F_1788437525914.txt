# GitHub Project Health Agent — Phase 1: Portable Project Foundation

You are the lead software engineer building a serious portfolio project called:

**GitHub Project Health Agent**

The goal is to build an evidence-driven AI-powered system that analyzes a public GitHub repository and produces a Project Health Report.

IMPORTANT:
This project must remain fully portable. I may stop using Replit at any point and continue development using Claude Code or another coding agent from the same GitHub repository.

Therefore:

## 1. PORTABILITY IS A HARD REQUIREMENT

Do NOT make the application dependent on Replit-specific services or infrastructure unless absolutely necessary.

The application must be runnable outside Replit using standard local development environments.

Use:

* Python
* FastAPI
* Next.js
* TypeScript
* Tailwind CSS
* GitHub REST API

Do not introduce unnecessary technologies.

Do NOT add:

* authentication
* PostgreSQL
* Redis
* Celery
* Kubernetes
* microservices
* complex agent frameworks
* automatic code fixing
* automatic commits
* automatic pull requests
* automatic issue creation

These are outside the MVP scope.

Create this structure:

---

# 3. BACKEND FOUNDATION

Create a FastAPI backend.

Create:

backend/app/main.py

with:

* FastAPI application
* CORS configuration for local frontend development
* GET / health endpoint
* clean application structure

Create:

backend/app/api/routes/analysis.py

Prepare the main endpoint:

POST /api/analyze

Expected request:

{
"repository_url": "https://github.com/owner/repository"
}

For now, the endpoint can return a structured placeholder response.

Do NOT implement the entire repository analyzer yet.

The purpose of this phase is to establish a clean architecture.

---

# 4. GITHUB URL VALIDATION

Create a reusable GitHub URL parser/validator.

It must:

* accept normal GitHub repository URLs
* extract owner
* extract repository name
* reject invalid URLs
* reject non-GitHub URLs
* handle trailing slashes
* handle .git suffix if present

Example:

https://github.com/torvalds/linux

should produce:

owner = "torvalds"
repo = "linux"

Keep this functionality isolated in a reusable module.

---

# 5. GITHUB CLIENT ARCHITECTURE

Create:

backend/app/github/client.py

and

backend/app/github/repository.py

The GitHub client should use standard HTTP requests through `httpx`.

Prepare the architecture for:

* repository metadata
* repository tree
* individual file contents

Do not download arbitrary repositories using shell commands.

Use the GitHub REST API.

The GitHub API token, if later required, must come from an environment variable.

NEVER hardcode API keys or tokens.

---

# 6. ENVIRONMENT VARIABLES

Create:

backend/.env.example

Include placeholders such as:

GITHUB_TOKEN=
OPENROUTER_API_KEY=

Do not put real credentials anywhere in the repository.

Create documentation explaining that secrets must be supplied through environment variables.

Never commit .env files.

---

# 7. FILE FILTERING FOUNDATION

Create:

backend/app/utils/filtering.py

Prepare reusable logic for repository file filtering.

The analyzer will eventually ignore:

.git/
node_modules/
venv/
.venv/
dist/
build/
coverage/
**pycache**/
target/
vendor/

Also ignore:

* images
* videos
* archives
* binary files
* generated files
* extremely large files

Add safety limits:

MAX_FILES = 500

MAX_FILE_SIZE = 200 KB

MAX_TOTAL_SOURCE_SIZE = 10 MB

These should be configurable constants, not scattered magic numbers.

frontend/app/page.tsx
