## OBJECTIVE

Implement the real repository ingestion pipeline:

GitHub Repository URL
→ Validate URL
→ Fetch Repository Metadata
→ Fetch Repository File Tree
→ Filter Relevant Files
→ Fetch Relevant File Contents
→ Return structured repository data

This is the foundation for all later analysis modules.

---

# 1. GITHUB CLIENT

Complete:

backend/app/github/client.py

Use `httpx`.

Implement clean methods for GitHub REST API operations.

The client should support:

### Repository metadata

GET:

/repos/{owner}/{repo}

Collect useful fields such as:

* name
* full_name
* owner
* description
* html_url
* default_branch
* stargazers_count
* forks_count
* open_issues_count
* language
* size
* topics if available

### Repository tree

Use the Git Trees API.

Fetch the recursive repository tree for the default branch.

The implementation should distinguish:

* files
* directories

Do not download file contents yet during tree discovery.

---

# 2. GITHUB API AUTHENTICATION

Support an optional GitHub token.

Read:

GITHUB_TOKEN

from environment variables.

If the token exists:

send it using the appropriate GitHub authorization header.

If the token does not exist:

the application should still attempt to work with public repositories.

Do NOT hardcode any token.

Do NOT expose tokens in logs or API responses.

# 3. ERROR HANDLING

* invalid GitHub URL

* private repository

* GitHub rate limit
* repository tree unavailable
* individual file unavailable
* GitHub API timeout
* unexpected GitHub API response

Return useful application-level errors.

Do not expose raw stack traces to frontend users.

# 5. FILE SIZE LIMIT

Do not download excessively large files.

Use the existing safety limit:

MAX_FILE_SIZE = 200 KB

If a file exceeds this limit:

* skip downloading it
* record that it was skipped
* do not treat it as an error
* include the reason in repository analysis metadata

---

# 6. FILE COUNT LIMIT

Use:

MAX_FILES = 500

Only analyze up to 500 relevant files.

If the repository contains more than the limit:

* select relevant source/config/documentation files first
* skip low-priority files
* record that the repository was truncated

Do NOT randomly download thousands of files.

---

# 7. TOTAL SOURCE SIZE LIMIT

Use:

MAX_TOTAL_SOURCE_SIZE = 10 MB

Track the cumulative size of downloaded text files.

Stop downloading additional files when the limit is reached.

Record:

* total downloaded size
* number of downloaded files
* number of skipped files
* reason for skipping

# 9. FILE CONTENT FETCHING

Implement a method that fetches an individual file from GitHub.

Use the GitHub Contents API where appropriate.

The method should:

* fetch content
* decode Base64 correctly
* return text
* respect MAX_FILE_SIZE
* gracefully handle files that cannot be decoded
* never return binary content as text

If a file cannot be safely decoded:

skip it and record the reason.
